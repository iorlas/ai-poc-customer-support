# Data Model: RAG-Based Customer Support Chatbot

**Feature**: 001-rag-support-chatbot
**Date**: 2025-11-04
**Phase**: 1 (Design & Contracts)

## Overview

This document defines the core entities, their fields, relationships, validation rules, and state transitions for the RAG-based customer support chatbot.

---

## Entity Definitions

### 1. User Session

**Description**: Represents an individual customer's interaction with the chatbot, including conversation history and context.

**Storage**: Streamlit `st.session_state` (in-memory, per browser session)

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `messages` | `list[Message]` | Yes | Conversation history | Non-empty list after first interaction |
| `session_id` | `str` | Yes | Unique session identifier | Auto-generated by Streamlit |

**Lifecycle**:
- **Created**: On first page load (Streamlit session start)
- **Updated**: After each user message + assistant response
- **Destroyed**: On browser tab close or session timeout

**Python Type**:
```python
# Managed by Streamlit, not explicitly modeled
# Accessed via: st.session_state.messages
```

---

### 2. Message

**Description**: A single turn in the conversation, either from the customer (question) or chatbot (response), with timestamp.

**Storage**: Part of User Session in `st.session_state.messages`

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `role` | `Literal["user", "assistant", "system"]` | Yes | Message sender | Must be "user" or "assistant" (system for context) |
| `content` | `str` | Yes | Message text | Non-empty string |
| `timestamp` | `datetime` | No | When message was created | ISO8601 format |

**Python Type**:
```python
from pydantic import BaseModel
from datetime import datetime

class Message(BaseModel):
    role: str  # "user" | "assistant" | "system"
    content: str
    timestamp: datetime | None = None  # Optional for POC
```

---

### 3. Document

**Description**: A knowledge base artifact containing information that can be queried, with metadata (title, upload date, document type).

**Storage**: Original files in `documents/` directory; processed chunks in ChromaDB

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `file_path` | `str` | Yes | Path to document file | Must exist, supported extension (.pdf, .txt, .md) |
| `file_name` | `str` | Yes | Document filename | Derived from path |
| `file_type` | `Literal["pdf", "txt", "md"]` | Yes | Document format | Based on file extension |
| `text_content` | `str` | Yes | Extracted text | Non-empty after parsing |
| `upload_date` | `datetime` | No | When indexed | ISO8601 format |

**Lifecycle**:
- **Created**: When added to `documents/` directory
- **Indexed**: Via `indexing_script.py` (manual execution)
- **Chunked**: Split into Document Chunks by Chonkie
- **Embedded**: Stored in ChromaDB collection

**Python Type**:
```python
from pydantic import BaseModel
from pathlib import Path
from datetime import datetime

class Document(BaseModel):
    file_path: Path
    file_name: str
    file_type: str  # "pdf" | "txt" | "md"
    text_content: str
    upload_date: datetime | None = None
```

---

### 4. Document Chunk

**Description**: A fixed-size segment of a document (512 tokens with 128 token overlap) that can be independently embedded, retrieved, and referenced.

**Storage**: ChromaDB collection `support_docs`

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `chunk_id` | `str` | Yes | Unique identifier | Format: `{file_name}_chunk_{index}` |
| `text` | `str` | Yes | Chunk content | 1-512 tokens (enforced by Chonkie) |
| `token_count` | `int` | Yes | Number of tokens | 1-512 |
| `start_index` | `int` | Yes | Start position in original document | >= 0 |
| `end_index` | `int` | Yes | End position in original document | > start_index |
| `source_document` | `str` | Yes | Source filename | Must reference existing document |

**Metadata** (stored in ChromaDB):
```json
{
  "source": "faq.pdf",
  "start_index": 0,
  "token_count": 512
}
```

**Python Type**:
```python
from chonkie import Chunk  # Chonkie provides this

# Chonkie Chunk attributes:
# - .text: str
# - .token_count: int
# - .start_index: int
# - .end_index: int
```

**Validation Rules**:
- `token_count` must be <= 512
- Overlap between consecutive chunks: ~128 tokens
- Each chunk must maintain semantic coherence (Chonkie handles this)

---

### 5. Embedding

**Description**: A numerical vector representation of text (document chunks or queries) used for semantic similarity matching.

**Storage**: ChromaDB (managed internally)

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `vector` | `list[float]` | Yes | Embedding values | Dimension based on model (BAAI/bge-small: 384-dim) |
| `chunk_id` | `str` | Yes | Associated chunk | References Document Chunk |

**Generation**:
- Model: `BAAI/bge-small-en-v1.5` (sentence-transformers)
- Dimension: 384
- Managed by ChromaDB embedding function

**Not explicitly modeled in application code** (ChromaDB abstraction)

---

### 6. Retrieval Result

**Description**: A document chunk matched to a user query, with relevance score and source reference.

**Storage**: Temporary (query response, not persisted)

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `text` | `str` | Yes | Chunk content | From ChromaDB results |
| `distance` | `float` | Yes | Cosine distance (0-2) | Lower = more similar |
| `similarity` | `float` | Yes | Similarity score (0-1) | Derived: `1 - distance` |
| `metadata` | `dict` | Yes | Source, token count, etc. | From ChromaDB metadata |

**Python Type**:
```python
from pydantic import BaseModel

class RetrievalResult(BaseModel):
    text: str
    distance: float
    similarity: float  # 1 - distance
    metadata: dict  # {"source": "faq.pdf", "start_index": 0, ...}
```

**Validation Rules**:
- `similarity > 0.7` (threshold filter applied post-retrieval)
- Maximum 3 results returned (top-3)

---

### 7. Support Ticket

**Description**: A simple escalation record stored in JSON Lines format, containing ticket_id (UUID or timestamp-based), timestamp (ISO8601), customer_message (text), status (always "open"), and optional conversation_context (list of prior messages). No update/close mechanism in this minimal implementation.

**Storage**: `tickets.jsonl` (append-only file)

**Fields**:
| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| `ticket_id` | `str` | Yes | Unique identifier | UUID4 format |
| `timestamp` | `str` | Yes | Creation time | ISO8601 format |
| `customer_message` | `str` | Yes | Customer's issue description | Non-empty string |
| `status` | `Literal["open"]` | Yes | Ticket status | Always "open" (no transitions) |
| `conversation_context` | `list[Message]` | No | Prior chat messages | Optional, up to last N messages |

**JSON Lines Format**:
```json
{"ticket_id": "123e4567-e89b-12d3-a456-426614174000", "timestamp": "2025-11-04T12:34:56Z", "customer_message": "I need help with my order", "status": "open", "conversation_context": [{"role": "user", "content": "What are your business hours?"}, {"role": "assistant", "content": "We're open 9-5 weekdays."}]}
```

**Python Type**:
```python
from pydantic import BaseModel, Field
from datetime import datetime
import uuid

class SupportTicket(BaseModel):
    ticket_id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    timestamp: str = Field(default_factory=lambda: datetime.utcnow().isoformat() + "Z")
    customer_message: str
    status: str = "open"
    conversation_context: list[Message] | None = None

# Usage with PydanticAI
def create_ticket(message: str, context: list[Message] | None = None) -> SupportTicket:
    return SupportTicket(
        customer_message=message,
        conversation_context=context
    )
```

**Validation Rules**:
- `ticket_id` must be unique (UUID4 ensures this)
- `timestamp` must be valid ISO8601
- `status` cannot change (always "open" in POC)
- File operations fail-fast on corruption/missing file

**State Transitions**:
```
[None] --> [open]  (create only, no updates)
```

## Relationships

```
Document (1) --chunks--> (N) Document Chunk
Document Chunk (1) --has--> (1) Embedding
User Query --retrieves--> (0-3) Retrieval Result
Retrieval Result --references--> (1) Document Chunk
User Session (1) --contains--> (N) Message
Message --may trigger--> (0-1) Support Ticket
Support Ticket (1) --includes--> (0-N) Message (conversation_context)
```

---

## Data Flow

### Indexing Flow (Offline)
```
1. Document (file) → load_document() → text_content
2. text_content → TokenChunker.chunk() → Document Chunks
3. Document Chunks → ChromaDB.add() → Embeddings (auto-generated)
```

### Query Flow (Runtime)
```
1. User Message → st.chat_input()
2. User Message → ChromaDB.query() → Retrieval Results
3. Filter Retrieval Results (similarity > 0.7) → top-3 chunks
4. Chunks → format as context → LLM prompt
5. LLM response → Message (assistant role)
6. If tool_call → execute submit_ticket/find_ticket → Support Ticket
```

## Validation Summary

| Entity | Key Validation Rules |
|--------|---------------------|
| **Message** | role in ["user", "assistant", "system"], content non-empty |
| **Document** | file exists, extension in [.pdf, .txt, .md], text_content non-empty |
| **Document Chunk** | token_count <= 512, start_index < end_index, source references valid document |
| **Retrieval Result** | similarity > 0.7 (threshold), max 3 results |
| **Support Ticket** | ticket_id is UUID4, timestamp is ISO8601, status always "open" |

## Storage Layer Summary

| Entity | Storage Mechanism | Persistence |
|--------|------------------|-------------|
| **User Session** | Streamlit session state | Temporary (session lifetime) |
| **Message** | Streamlit session state | Temporary (session lifetime) |
| **Document** | Files in `documents/` | Permanent (manual management) |
| **Document Chunk** | ChromaDB collection | Permanent (./chroma_db/) |
| **Embedding** | ChromaDB (internal) | Permanent (./chroma_db/) |
| **Retrieval Result** | In-memory (query response) | Temporary (request lifetime) |
| **Support Ticket** | JSON Lines file (tickets.jsonl) | Permanent (append-only) |

---

## Notes

- **Fail-Fast Philosophy**: No error recovery for corrupted files, missing data, or invalid states (POC scope)
- **No Authentication**: All users share same ChromaDB collection; no user isolation
- **No Audit Trail**: Ticket updates/closes not supported; status always "open"
- **Stateless Retrieval**: Each query is independent; no query history tracking
